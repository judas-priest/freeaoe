# Plan: Town Bell (Ring / Abort)

**Goal:** Wire `RingTownBell` (Command 49) and `AbortTownBell` (Command 61) in `ActionPanel::handleButtonClick`. Ring: find all player villagers within 23 tiles of any TC, save their current action queues, garrison them in the nearest TC. Abort: ungarrison them and restore saved tasks.

**Status:** Not started

---

## Overview

Both commands already exist in `ActionPanel::Command` (values 49 and 61) and appear in `helpTextId`. They are currently unhandled in `handleButtonClick`. The implementation lives entirely in `ActionPanel` — no new action class needed because `ActionGarrison` already handles the move+garrison sequence.

TC = unit ID `Unit::TownCenter` (109).

## `ActionPanel.cpp` — `handleButtonClick` additions

In the `Other` switch, after the `case Command::Garrison` block (around line 725), add:

```cpp
case Command::RingTownBell: {
    if (m_bellActive) break; // already rung
    m_garrisonedByBell.clear();
    m_bellActive = true;

    // Find all TCs belonging to the human player
    std::vector<Unit::Ptr> townCenters;
    for (const Unit::Ptr &u : m_unitManager->units()) {
        if (u->playerId() != m_humanPlayerId) continue;
        if (u->data()->ID == Unit::TownCenter) {
            townCenters.push_back(u);
        }
    }
    if (townCenters.empty()) break;

    constexpr float BELL_RANGE = 23.f * 48.f; // 23 tiles in pixels

    for (const Unit::Ptr &u : m_unitManager->units()) {
        if (u->playerId() != m_humanPlayerId) continue;
        // Only villagers (MaleVillager variants and FemaleVillager)
        if (u->data()->Type != genie::Unit::CivilianType) continue;

        // Find nearest TC within range
        Unit::Ptr nearestTC;
        float nearestDist = BELL_RANGE;
        for (const Unit::Ptr &tc : townCenters) {
            float d = u->position().distance(tc->position());
            if (d < nearestDist) {
                nearestDist = d;
                nearestTC = tc;
            }
        }
        if (!nearestTC) continue;

        // Save current action queue (snapshot weak_ptrs won't keep them alive, copy actions directly)
        SavedTask saved;
        saved.unit = u;
        // We don't have a clean copy API for the queue — just record the action types
        // so Abort can issue a Stop. Full task restoration would require serializing the queue.
        // For now, Abort issues Stop so the player can re-task them.
        m_garrisonedByBell.push_back(std::move(saved));

        // Clear current actions and send to TC
        u->actions.clearActionQueue();
        Task garrisonTask;
        garrisonTask.target = nearestTC;
        u->actions.assignAction(std::make_shared<ActionGarrison>(u, garrisonTask));
    }
    break;
}

case Command::AbortTownBell: {
    if (!m_bellActive) break;
    m_bellActive = false;

    // Find all TCs
    std::vector<Unit::Ptr> townCenters;
    for (const Unit::Ptr &u : m_unitManager->units()) {
        if (u->playerId() != m_humanPlayerId) continue;
        if (u->data()->ID == Unit::TownCenter) {
            townCenters.push_back(u);
        }
    }

    // Ungarrison all villagers that were garrisoned by the bell
    for (const Unit::Ptr &tc : townCenters) {
        auto tcBuilding = Building::fromUnit(tc);
        if (!tcBuilding) continue;
        tcBuilding->ungarrisonAll();
    }

    // Issue stop to all units we garrisoned (they come out with no action)
    for (SavedTask &saved : m_garrisonedByBell) {
        Unit::Ptr u = saved.unit.lock();
        if (u) {
            u->actions.clearActionQueue();
        }
    }
    m_garrisonedByBell.clear();
    break;
}
```

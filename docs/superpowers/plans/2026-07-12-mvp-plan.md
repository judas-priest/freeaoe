## Phase 1: Critical Blockers (must fix to even play)

### Task 1: Fix SDL window lifecycle (TWO bugs)

**Problem:** App crashes with "Android only supports one window".

**Root cause (from deep audit):** There are actually TWO window bugs:
1. ScenarioBrowser creates+destroys its window, then Engine creates one — this transition IS safe (SDL_DestroyWindow fully releases)
2. **The REAL crash: `UiScreen::init()` at `UiScreen.cpp:228` creates a THIRD SdlWindow while Engine's window is still alive.** Engine creates `m_sdlWindow` (line 884), then calls `m_mainScreen->init()` (line 897) which creates its own SdlWindow because `m_renderTarget` is null on UiScreen. In SFML path, Engine calls `setRenderWindow()` first — but there's no SDL2 equivalent.

**Four SdlWindow creation sites in codebase:**
- `FileDialog.cpp:87` — FileDialog::setup() (never called on Android)
- `UiScreen.cpp:228` — UiScreen::init() ← THE CRASH
- `ScenarioBrowser.cpp:120` — ScenarioBrowser::run() (properly destroyed)
- `Engine.cpp:884` — Engine::setup()

**Fix:** Two changes:
1. Add `setRenderTarget()` to UiScreen for SDL2 (mirrors SFML's `setRenderWindow()`)
2. Pass Engine's renderTarget to UiScreen before init() — prevents UiScreen from creating its own window

**Files:**
- Modify: `src/ui/UiScreen.h` — add setRenderTarget() for SDL2
- Modify: `src/ui/UiScreen.cpp` — implement setRenderTarget()
- Modify: `src/Engine.cpp:897` — call setRenderTarget before init()

- [ ] **Step 1: Add setRenderTarget() to UiScreen**

In `src/ui/UiScreen.h`, add alongside existing setRenderWindow:

In `src/ui/UiScreen.cpp`, implement:

### Task 2: Fix terrain PNG rendering (3 bugs)

**Problem:** PNG terrain textures found but map is black.

**Root cause (from deep audit — 3 bugs):**

**BUG A — NULL POINTER DEREFERENCE (crash):** `TerrainSprite.cpp:101` calls `m_slp->getFrameCount()` when `m_slp` is null. For PNG terrain, `m_isPng=true` and `m_slp=nullptr`. The code skips the fallback at line 95 (`if (!m_slp && !m_isPng)`) but still reaches line 101 where `m_slp->getFrameCount()` crashes.

**BUG B — pngTexture() sourcePos out of bounds:** `pngTexture()` (line 138-247) samples at `sourcePos = MapPos(x,y).toScreen() + ScreenPos(96, 48)`. sourcePos.x can reach 240, but HD terrain PNGs may be smaller → bounds check at lines 189-190 skips all pixels → output is all zeros (black).

**BUG C — tile.frame ignored:** `pngTexture()` never uses `tile.frame` — every tile gets identical texture. `coordinatesToFrame()` has a hardcoded `sqrt(4*4)=4` for PNG path.

**Files:**
- Modify: `src/resource/TerrainSprite.cpp:56-101` — fix null deref, set m_tileSquareCount
- Modify: `src/resource/TerrainSprite.cpp:138-247` — fix sourcePos calculation
- Modify: `src/resource/TerrainSprite.h:50-61` — fix coordinatesToFrame for PNG

- [ ] **Step 1: Fix null deref — skip m_slp->getFrameCount() when m_isPng**

At `TerrainSprite.cpp:95-101`, change:
```cpp
    if (!m_slp && !m_isPng) {
        WARN << "Failed to get slp for" << data->SLP;
        m_slp = AssetManager::Inst()->getSlp(15000);
        return;
    }
    m_tileSquareCount = sqrt(m_slp->getFrameCount());
```
To:
```cpp
    if (m_isPng) {
        m_tileSquareCount = data->TerrainDimensions.first; // Usually 10 for HD
        return; // PNG path complete, don't touch m_slp
    }
    if (!m_slp) {
        WARN << "Failed to get slp for" << data->SLP;
        m_slp = AssetManager::Inst()->getSlp(15000);
        return;
    }
    m_tileSquareCount = sqrt(m_slp->getFrameCount());
```

- [ ] **Step 2: Fix pngTexture() coordinate sampling**

The sourcePos calculation uses `MapPos(x,y).toScreen()` which gives screen coords way outside PNG bounds. The PNG is a tiled texture sheet — need to sample using simple tile-grid coordinates, not isometric conversion. Check the HD PNG dimensions on device:
```bash

```
Then fix sourcePos to sample from the correct tile region within the PNG.

- [ ] **Step 3: Fix coordinatesToFrame to use m_tileSquareCount for PNG**

In `TerrainSprite.h:54-56`, change the hardcoded `sqrt(4*4)`:
```cpp
if (m_isPng) {
    return (y % m_tileSquareCount) + (x % m_tileSquareCount) * m_tileSquareCount;
}
```

- [ ] **Step 2: Implement queued playback**

In `AudioPlayer.cpp`, modify `playStream()`:
```cpp
bool AudioPlayer::playStream(const std::string &filename) {
    if (m_activeStreams.count(filename)) return true;

    if (m_streamPlaying) {
        // Queue for later
        m_streamQueue.push(filename);
        return true;
    }
    m_streamPlaying = true;
    // ... existing stream loading code ...
}
```

**IMPORTANT threading constraint:** `mp3StopCallback` fires on the audio thread (inside `malCallback` which holds `m_mutex`). Cannot call `playStream()` from the callback (would deadlock on mutex). Instead, set an atomic flag and drain the queue from the main game loop.

In `mp3StopCallback()`, just set a flag:
```cpp
void AudioPlayer::mp3StopCallback(const int id, sts_mixer_sample_t *sample, void *userdata) {
    // ... existing cleanup ...
    auto &inst = AudioPlayer::instance();
    inst.m_streamPlaying = false;  // atomic or set under existing lock
}
```

Add a `tick()` method called from the game loop:
```cpp
void AudioPlayer::tick() {
    if (!m_streamPlaying && !m_streamQueue.empty()) {
        std::string next = m_streamQueue.front();
        m_streamQueue.pop();
        playStream(next);  // safe — called from main thread
    }
}
```

Call `AudioPlayer::instance().tick()` from `Engine::start()` game loop (where `state->update()` is called).

Test: scenario with multiple dialogue triggers → sounds play one after another, not overlapping.

### Task 4: Fix scenario localization (2 bugs)

**Problem:** Scenario dialogue is in English.

**Root cause (from deep audit):** Two independent bugs:

**BUG A — stringTableID ignored:** `ScenarioController.cpp:369` uses `effect.message` (literal English text from .scn file) and NEVER checks `effect.stringTableID`. The HD scenarios carry BOTH a `stringTableID` (index into LanguageManager strings) AND a fallback `message`. Original AoE2 uses stringTableID when >= 0, freeaoe always uses message.

**BUG B — Audio paths hardcoded to English:** `AssetManager_HD.h:186-197` `locateStreamFile()` searches only `resources/en/sound/`, `resources/en/campaign/sound/`, etc. Never checks language-specific dirs. Has comment `// TODO: other languages?`

**Files:**
- Modify: `src/mechanics/ScenarioController.cpp:369` — use stringTableID when available
- Modify: `src/resource/AssetManager_HD.h:186-197` — add language-specific audio paths

- [ ] **Step 1: Use stringTableID for DisplayInstructions**

In `ScenarioController.cpp`, change the DisplayInstructions handler:
```cpp
case genie::TriggerEffect::DisplayInstructions: {
    AudioPlayer::instance().playStream("scenario/" + effect.soundFile + ".mp3");
    std::string msg = effect.message;
    if (effect.stringTableID >= 0) {
        std::string localized = LanguageManager::getString(effect.stringTableID);
        if (!localized.empty()) {
            msg = localized;
        }
    }
    if (m_engine) {
        m_engine->addMessage(msg);
    }
    break;
}
```

Add `#include "resource/LanguageManager.h"` at top.

- [ ] **Step 2: Add language-specific audio paths**

In `AssetManager_HD.h`, `locateStreamFile()`, prepend language-specific paths:

```cpp
const std::string lang = Config::Inst().getValue(Config::Language);
static const std::vector<std::string> possibleFolders = {
    "resources/_common/sound/stream/",
    "resources/" + lang + "/sound/",          // language-specific first
    "resources/" + lang + "/campaign/sound/",
    "resources/" + lang + "/sound/scenario/",
    "resources/en/sound/",                    // English fallback
    "resources/en/campaign/sound/",
```

Note: `static` won't work with runtime `lang` — use a local variable instead.
